Use Ixel

Handoff: agents as a team

Say "Codex, take the tests; Claude, do the API" and the work, notes and reviews pass between them through a task board they share. You stop being the one who copies and pastes between AI apps.

How it works

Each project (a git repository) gets one board, a small database in the project's .handoff folder. Each of your AI apps gets a handoff plugin (an MCP server) that reads and writes that board under the app's own name. Agents create tasks, hand them to each other with notes on what's done, what's left and how to check it, and ask each other for reviews.

Nothing wakes the other app up. An AI app only acts when you prompt it, and a plugin can't push a message into a chat. So after one agent hands work over, you switch to the other app and say:

check your handoffs

That's the whole routine. A new Claude Code session hears what's waiting for it on its own.

Handoff itself stores and serves text. It doesn't edit your files or call a model; the agents do the work with their own tools and their own approvals. It never listens on the network.

Connect your apps

Handoff comes with Ixel's installer. In your project's folder, run:

handoff setup --write

Then restart the apps. It only touches apps that are installed, keeps everything else in their settings, and is safe to run again. handoff setup without --write shows what it would add, and handoff setup --remove takes it all out again.

AppWhich project it usesHears what's waiting on its own
Claude CodeThe folder you open it in, so one setup covers every projectYes, when a session starts
Codex (CLI, IDE extension or app)The folder you run it inNo, say "check your handoffs"
Gemini CLIThe folder you run it inNo
OpenCodeThe folder you run it inNo
Grok BuildThe folder you run grok inNo
Claude DesktopThe project you ran setup in (it has no folder of its own); run setup in another project to switchNo

Claude Code's session start note says only which tasks are waiting, by number ("2 tasks are assigned to you: T-3, T-7"), never their titles or notes. --no-hook leaves it out.

ChatGPT

The ChatGPT app isn't supported: it only connects to plugins on the internet, and Handoff never listens on the network. Codex signs in with the same ChatGPT subscription and works.

handoff doctor checks the project, the board, and which apps have Handoff set up.

Walkthrough

You're adding an orders endpoint, and you want Codex on the tests while Claude builds the endpoint.

  1. In Claude Code or Claude Desktop

    Split this feature. Hand the tests to Codex, and you do the endpoint.

    Claude makes two tasks: Add /api/orders for itself, and Tests for /api/orders for Codex, with notes and checks to meet ("tests/test_orders.py covers GET and POST"). It claims the files it will change, starts on the endpoint, and tells you to ask Codex to check its handoffs.

  2. In Codex

    Check your handoffs.

  3. Back in Claude

    Anything from Codex?

    Claude reads the handoff, finishes the endpoint and runs the tests. It asks Codex to review the endpoint (or asks your Ixel panel). Codex marks each check met, not met or not checked, so Claude sees exactly what still needs work. When the review approves, Claude marks both tasks done.

    handoff T-2 prints one task with its whole history, and what you can do with it next:

    The Board in the Ixel app shows the same board in columns, and lets you act on each task with a click.

Hand out a whole list at once

Start each part with who does it, and Handoff splits the request by plain rules (no model guesses), shows you the plan, and on a yes runs every part at the same time:

KindWhoWhere the result is
Change files ("finish", "fix", "build", "the next step")claude, codexA branch of its own, handoff/T-N, for you to review and merge
Review ("review", "audit")Any model you added in ixel setupThe task, and .handoff/outputs/T-N/answer.md
Answer (anything else)Any model you added in ixel setupThe task, and .handoff/outputs/T-N/answer.md
Pictures ("make pictures", "draw a logo")grok (xAI), gpt (OpenAI), with your key.handoff/outputs/T-N/

A part that can't run here says why (not set up, no key, nothing to review) and the rest still run. handoff agents shows who can do what on this computer. In the Ixel app, type /handoff in Ask to do the same thing.

Let an agent work while you're away

The worker (a preview) runs Claude Code or Codex on one task you approve, in a copy of your project on a branch of its own. It never pushes, and your own checkout isn't touched:

handoff approve T-7 codex       # you approve one task, for one run
handoff worker --agent codex    # runs it, then waits for your next approval
  • Linux: the agent runs inside a sandbox (bubblewrap) that shows it only that copy of your files and none of your home folder, and the commands it runs have no network. It can run your tests and builds.
  • Mac and Windows, for now: Claude Code only, and edit-only: it can read and change files, but can't run commands, tests or builds, and its handback says so.

When it's done, the worker commits its changes on handoff/T-7 and hands the task back with what was done, what's left, and how to check it. You review the branch and merge it yourself. An approval is good for one run, only on the computer where you made it, and only while the task is as you approved it.

Your controls

At the command line you're human on the board, shown as "you", and you can do what agents can't. me means you wherever you name someone.

CommandWhat it does
handoff, handoff board --watchThis project's board; --watch keeps it refreshing
handoff T-12One task with its whole history
handoff add "title" --to codexAdd a task (with no title, it asks what needs doing and who should do it)
handoff assign T-12 claudeGive a task to someone else (me, or nobody)
handoff note T-12 "text"Add a note to any task
handoff review T-12Review a task waiting for you: approve, or send it back with changes
handoff done T-12, reopen, block T-12 "why"Close, reopen, or block a task
handoff cancel T-12, delete T-12Cancel (keeps the history), or delete for good (asks first)
handoff done-rule reviewAgents may mark tasks done only after an approving review
handoff update, handoff helpGet the latest Handoff; every command

The rules

The board checks these itself. It doesn't trust what an agent says about who it is.

  • Only the assignee can add notes to a task, hand it on, ask for a review or change its status. Nobody reviews their own work.
  • Done needs a review, or a reason. By default an agent can mark a task done after an approving review, or by saying why it doesn't need one.
  • History is kept. Agents can't delete tasks or edit the history; only you can, from the command line.
  • Files are claimed, not locked. When two active tasks claim the same files, both agents are warned.
  • No secrets. Text that looks like an API key, a token or a private key is refused, not stored.
  • The board is information, not orders. When an agent reads it, Handoff tells it the text was written by other agents or by you, to weigh rather than obey.
Agents with a shell

These rules bind the plugin. An agent that can run commands as you (Claude Code's Bash, Codex's shell) can also run the handoff command as you. Deny it handoff approve, handoff delete and handoff run in its permission settings.

Where things live

  • The board is .handoff/board.db in your project. On a Mac and Linux, only you can read it. It keeps every task's text and history until you delete the task or the folder; Privacy has more.
  • .handoff/ keeps itself out of git, so the board isn't committed with your work.
  • Handoff has no settings of its own, so nothing in a project folder can make Handoff run anything.

Troubleshooting

  • "No project found": run the command inside your project (a git repository), or add --project PATH. If an app says this, run handoff setup --write in the project and restart the app.
  • An agent can't see a task: ask it to look at the board. Tasks are per project, so check the app is open in the same project. handoff doctor shows where Claude Desktop points.
  • Codex gives up on a review with the Ixel panel: raise tool_timeout_sec under [mcp_servers.handoff] in ~/.codex/config.toml.
