Models

Local models

A model running on your own computer costs nothing per question, has no usage limit, and keeps your questions at home. Ixel works with Ollama, LM Studio, and any model server that speaks OpenAI's chat API.

Picks from Artificial Analysis, read 4 October 2026

Set one up

Ixel doesn't run models itself: a model server does, and Ixel asks it. Pick one:

Ollama

  1. Install Ollama

    From ollama.com. It runs in the background, ready for Ixel at 127.0.0.1:11434.

  2. Download a model

    Pick one from the table below, find it in Ollama's library, and download it:

    ollama pull <model>

  3. Add it to Ixel

    Run ixel setup. It sees Ollama running, lists your models, and asks which to add. No key needed.

LM Studio

  1. Install LM Studio

    From lmstudio.ai, and download a model in it. Pick one from the table below.

  2. Start its server

    Turn on LM Studio's local server, so other programs can ask the model. It listens at 127.0.0.1:1234.

  3. Add it to Ixel

    Run ixel setup. It sees LM Studio's server, lists your models, and asks which to add. No key needed.

Another server

Any server with OpenAI's chat API works (llama.cpp's server, vLLM, and others), on this computer or another one of yours. ixel setup only looks for Ollama and LM Studio on this computer, so add the others to your settings file, ~/.config/ixel-mat/config.toml:

[agents.gpubox]
type = "http"
url = "http://gpu-box:8000/v1/chat/completions"   # the server's address, with /v1/chat/completions
model = "the-model-name"                          # as the server lists it
label = "My GPU box (local)"

Then add "gpubox" to [review] agents if you've set that list, or leave it unset to have every model on the panel.

Before you run setup again

ixel setup writes your settings file afresh. A model you added by hand isn't kept; copy it back from config.toml.bak, which setup leaves beside it.

A model on another computer

A model server on another computer of yours works the same way: put its address in the url. Ixel counts a server on your own network or your Tailscale network as local, so its calls are free in the cost line. Plain http:// across a network isn't encrypted; over Tailscale it is.

Which model fits your computer

The best open models a computer with that much memory can run. On a Mac, count all your memory, since the graphics share it. On a PC, count your graphics card's memory: a model that doesn't fit there still runs, but much more slowly.

The best open models overall: MiMo-V2.6-Pro (46, 1000B, about 602 GB), GLM-5.3-Flash (42, 320B, about 194 GB), K2 Horizon 375B A23B (31, 375B, about 227 GB). Those need a server, or a Mac with a lot of memory.

"Needs" is an estimate: about 0.6 GB for each billion parameters, which is a typical 4-bit download, plus 2 GB for the conversation. A smaller download of the same model needs less and answers a little worse; a larger one needs more. Model servers often name models differently from the benchmark, so search for the model's name in Ollama's or LM Studio's library.

Scores are on the same scale as the cloud picks, so you can see what you give up. Today's best local models score well below the best cloud ones, which is why the mix below works well.

Mix local and cloud

The cheapest panel that still gets things right: local models do the drafting and reviewing, and one strong cloud model checks their work. That's Saver:

[saver]
verifier = "opus"                 # one strong model, on a key or a subscription
drafters = ["qwen", "gpubox"]     # your local models
verifier_effort = "low"           # it only has to check

Or in the app: Settings, Saver. The drafters' calls are free; the big model reads their drafts and replies in a few words, so it costs far less than writing the answer itself. The four jobs says more.

Pictures

A local model doesn't get the pictures you attach in the app, since most can't read them. For one that can, such as a vision model, turn it on in Settings, Pictures, or add accepts = ["image"] to its section of the settings file.

Thinking settings

Ixel sends a local model's thinking setting the way it does OpenAI's, so xhigh and max are sent as high, and whether the model uses it is up to the model and the server. The table above only counts the settings Ixel can send.

What stays on your computer

With only local models on your panel, and Triage off or deciding with one of them, your questions, your code and the answers go no further than the computer running the model. A few parts of Ixel reach the internet for other reasons, and none of them sends your questions:

  • The terminal chat checks GitHub for a new version once a day. [updates] check = false turns it off.
  • Sound sends a recording to OpenAI or Groq, and making pictures sends your description to xAI or OpenAI, only when you use them.
  • The Board reads a project's pull requests from its git host when you open it.
